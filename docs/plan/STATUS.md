## Current state

- **Phase:** v1 plan complete. Done: WP-00 – WP-20, WP-22 – WP-28, WP-30 – WP-34; WP-21 and WP-29 partly done (their open halves are blocked, see their rows).
- **Next:** improvement waves (UI, code quality, product), and the maintainer decisions below. WP-21's open half (souhrnné hlášení, EPO XML writers) is listed in its row.
- **Blocking decisions:** **the `AnthropicApi` driver (WP-29) conflicts with the network invariant.** D-005 adds an API-key driver, but CLAUDE.md allows the app no network except the user's own `claude` process, opt-in signed reference data and an opt-in update check, and an HTTPS client to the API would be a fourth path (and the API key is a credential the app would hold, in the OS keychain). Either amend the invariant (a fourth, opt-in path for users who bring their own API key, off by default, the key only in the keychain) or drop the driver from v1. Until then the driver isn't built; the live eval harness runs through the CLI. **Review needed (statutory):** the pack's `insurance.social.share` is 50 %, but § 5b odst. 1 ZOS as amended by zákon č. 349/2023 Sb. sets the OSVČ social-insurance assessment base at 55 % of the profit from 2024 (health insurance stays at 50 %). Correcting it changes the WP-22 worked example (197 584 Kč), the advisor transcripts and their tests, so it's recorded as an `open` golden case in `rules/cz/2026/golden.toml` rather than changed overnight; verify and fix the pack (closing the 50 % entry at 2023-12-31), then update the example. **Open for the maintainer:** create the release key and the rule-pack signing key (minisign; `docs/RELEASING.md`), add their public keys to `TRUSTED_RELEASE_KEYS` and `TRUSTED_PACK_KEYS`, and set the signing secrets; until then update checks and pack updates are refused (by design) and releases are unsigned. Wave 4 recorded as D-017 (dark first-class from WP-08) and D-018 (spike run in the cloud).
