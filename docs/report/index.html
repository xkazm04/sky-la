The v1 plan, milestone by milestone

Each work packet has its acceptance commands in docs/plan/IMPLEMENTATION_PLAN.md and its evidence in docs/plan/STATUS.md.

M0 · Foundation

WP-00 – WP-03
WP-00Scaffold, CI, cloud readinessDoneCargo and pnpm workspaces, Biome, justfile, CI on Linux, macOS and Windows, the licence-boundary check and the session hook.
WP-01Claude Code CLI spikeDoneThe hardened launch profile: canary-tested isolation, stdin closed (p50 about 1.35 s), a scrubbed environment and the stream-json parser. 10 of 11 checks pass; C6 needs a desktop.

M1 · Ledger kernel

WP-04Accounts, Czech chart, categoriesDoneThe chart as data with a validator; triggers guard its structure.

WP-06Periods, reversals, close, hash chainDoneThe open → closing → closed lifecycle, mirror reversals, and a SHA-256 chain that names the first tampered entry.
WP-07ProjectionsDoneTrial balance, P&L, balance sheet, cash basis and the VAT ledger. The golden journal matches the design canvas to the cent; a trial balance over 100 000 entries takes about 0.1 s.

Improvement waves 1–15

After the plan, each wave took one gap that a user of real books would hit: a placeholder, a demo-only shortcut or a backlog item. Each was fixed end to end in the core, the IPC, the UI and the tests.

WaveWhat changed
1 · New customers from the editor"New customer…" is checked by the core like every other field. The e2e suite now fails on any page or console error, which caught two real defects.
2 · Real books keep their workbenchBank state, policies, reference data, switches and pack updates persist in the encrypted file. This also fixed CSV import, which had no profile.
3 · PurchasesReceived invoices are recorded and checked (DIČ, period, duplicates, VAT) and itemised in the KH. This also fixed pseudonyms in real books.
4 · The books' own periodsreporting_periods() replaces the screens' hard-coded demo dates.
5 · Deadlines from the calendarInbox and Overview deadlines come from the obligations calendar, with a return and its KH as one item.
6 · Auto-lockThe session drops the books, key and connection after 15 minutes idle or on Lock now.
7 · Business detailsThe profile can be corrected; issued invoices keep their snapshot.
8 · A month in real booksAn end-to-end regression test, from invoice to export and reopen.
9 · Smaller desktop bundleThe mock transport and source maps are left out: 1.7 MB → 676 kB.
10 · Recurring invoicesTemplates from the editor; real books run them idempotently at open.
11 · Inbox approvals post"Approve and post" and "Approve N certain" go through the kernel and book their bank lines.
12 · Dismiss adviceAdvisor account suggestions become postings to approve; the inbox persists.
13 · Accept one line, undo a bookingAn undo is a reversal entry; settled invoices reopen.
14 · Edit draftsThe editor reopens a draft prefilled, and changes are checked like a new draft.
15 · Payment remindersOverdue invoices show the drafted reminder, with Copy text and Mark as sent; the app sends no email.

The invariants, and what holds them

Each rule from CLAUDE.md is enforced by code and guarded by a test, not left to convention.

InvariantEnforced by
Money is integer minor unitsskyla-money; clippy denies float_arithmetic in money and ledger crates
Posted entries are immutableRust checks and SQL triggers; corrections, undo and reminders all use reversals or new records
Every entry balances, in an open period, on leaf accountsKernel invariants I1, I3 and I4, in Rust and triggers; property tests
The LLM never writes to the ledgerTools are read, compute and propose only; a test calls all of them and finds the books unchanged; posting needs the user's approval in the inbox
Tax arithmetic lives in Rust; advisor figures are groundedskyla-tax-cz and the engine; the grounding validator rejects any ungrounded figure
Statutory values come from cited rule packsskyla-rules validation and 60 golden cases with full coverage
No network except three opt-in pathsscripts/check_security.py pins every socket, HTTP call and spawn; reference data and update checks are off by default
IBANs and personal IDs are never sentThe egress gate covers prompts and tool results; 512-case property tests; every run is in the register
Apache-2.0 kernel never depends on AGPL cratesThe licence-boundary check in just ci, and cargo-deny

What's open

Decisions for the maintainer

  • Blocking API-key driver vs the network invariantD-005 adds an API driver, but the invariant allows no fourth network path. Amend the invariant (opt-in, key in the keychain) or drop the driver from v1.
  • Review Social-insurance shareThe pack has 50 %; the law has set 55 % since 2024. It's recorded as an open golden case; the fix touches the worked example and transcripts.
  • To do Signing keysCreate the release and rule-pack minisign keys and the CI secrets. Until then update checks and pack updates are refused, and releases are unsigned.

Next work (from the backlog)

  • Souhrnné hlášení and EPO XMLNeeds an EU-supply VAT code first, and the official schemas.
  • Real anonymised bank samplesOne per format from each major Czech bank; then re-measure the matcher.
  • Invoicing gapsReminder holds, tax point and buyer reference, refunds, multi-currency, native save dialog.
  • Desktop-only checksCLI check C6, lock on sleep, the isolation pattern, the first tagged release.
